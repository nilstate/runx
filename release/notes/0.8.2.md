# Runx CLI 0.8.2

Runx 0.8.2 closes the remaining gaps between prepared operator context,
runtime authority, packaged execution, and receipt verification. It removes
parallel resolution and test projections, preserves nested registry identity,
keeps human approval distinct from agent work, and proves the real extracted
CLI on every release platform before anything publishes.

## Highlights

- Registry-backed skill graphs now resolve and execute through one canonical
  loader, preserving verified package identity throughout nested execution.
- Human approval is host-attested authority, never an agent answer; the
  runtime enforces that distinction at the shared resolution boundary.
- Packaged candidates now prove their actual operator semantics across the
  release matrix, including adjacent workers, declared environment, large
  context, opaque scopes, one approval, and interruption.
- Receipt verification now has one runtime-owned precedence rule shared by
  verify, history, doctor, and receipt services.
- CLI parity tests consume the native Rust command catalog directly instead of
  maintaining generated TypeScript and JSON mirrors.

## Added

- Cross-platform semantic smoke tests that run against each extracted release
  archive before publication.
- Native resolution-answer handling that separates task output from explicit
  human approval decisions.
- A canonical receipt-verifier resolution result that includes the trusted
  source used by the runtime.
- Release evidence checks that require both `checks` and `gitleaks` to pass for
  the exact candidate commit.
- Provider-field guidance for Slack search operators, including keyword,
  channel, and time-bound shapes.

## Changed

- Nested registry graph children now use the same signed, verified loader at
  inspection, identity generation, and execution.
- Local sub-skill profile labels remain package-relative without introducing a
  second resolver.
- Inline harness and resume handling preserve approval provenance instead of
  flattening every response into a generic answer.
- CLI feature-parity coverage now derives command and runtime relationships
  from the Rust-owned catalog.
- The official Slack package and lock now publish the clarified search
  contract.

## Fixed

- Prevented signed registry closures from drifting between inspected and
  executed child packages.
- Rejected agent-authored approval decisions at the central runtime boundary
  while exposing the exact pending gate to provider execution.
- Derived a trusted verifier from a complete signing identity when an explicit
  public verifier is not configured, without changing explicit-verifier
  precedence.
- Kept history, verify, doctor, and receipt services aligned on the same
  verifier and its resolution source.
- Treated X's exact inactive-account unfollow response as already satisfied
  while leaving every other provider error fail-closed.
- Tightened strict-lint coverage without weakening approval or native-help
  assertions.

## Removed

- The parallel local child resolver for registry-backed execution closures.
- Generated CLI parity JSON projections and their TypeScript-only generator.
- The TypeScript oracle dependency from native Rust CLI command coverage.
- Duplicate receipt-verifier selection logic across CLI and runtime services.

## Security

- Approval gates accept only explicit host-attested human decisions; agent
  task output cannot authorize a consequential effect.
- Signed registry package identity remains bound through nested closure
  inspection and runtime admission.
- Release publication is blocked unless the exact immutable candidate commit
  passed both repository checks and secret scanning.
- Extracted release archives must preserve declared environment boundaries,
  opaque scopes, complete digest-bound operator context, and process
  interruption behavior before any package channel publishes.
- Explicit public verifier configuration remains authoritative; signing
  identity fallback is used only when the full signing identity is present.

## Breaking changes

- None. Existing v1 contracts were updated in place; this release does not add
  a parallel contract family.

## Upgrade guidance

- Upgrade with `npm install --global @runxhq/cli@0.8.2` or your existing Runx
  package-manager channel.
- Run `runx --version` and confirm `0.8.2`.
- Existing skill packages and v1 contracts require no migration.
